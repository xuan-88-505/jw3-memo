# PVP 装备库（魔盒数据）

内置计算器（`tools/dps-calculator`）原本只有 PVE 装备。这里从魔盒（JX3BOX）抓取当季的 PVP 装备、套装和 PVP 小附魔（化劲、御劲、铸世·归正，以及当季没有的往季属性），转换成计算器的格式，写到 `client/public/pvp-equip/`。计算引擎加载心法时会把这些数据合进去，配装器里就能选 PVP 装备，并算出化劲和御劲。

- 数据来源：魔盒公开接口 `https://node.jx3box.com/`，只读取，不需要登录。
- 产物：每个门派一个 json，另有 `common.json`（通用装和小附魔），共 22 个文件，约 1.8 MB。这些文件**要提交进 git**，因为打包时不联网抓取。
- 格式转换、挑选和属性计算都在 `client/src/lib/pvpEquip.ts`，单元测试在 `client/src/lib/pvpEquip.test.ts`。构建计算器时，这个文件会被复制成上游的 `src/备忘录PVP.ts`。

## 用法

```bash
npx tsx tools/pvp-equip/build.ts            # 抓取、校验并写入文件
npx tsx tools/pvp-equip/build.ts --check    # 只抓取和校验，不写文件
bash tools/dps-calculator/build.sh          # 改了 pvpEquip.ts 后要重新构建计算器
```

`build.sh` 的指纹包含 `pvpEquip.ts`，所以改了这个文件后会自动重新构建。只更新 json 不需要重新构建，引擎每次加载心法时都会重新读取。

脚本会和现有文件比较：内容没变的文件不动，`updatedAt` 也不改；有变化时打印每个文件的变更摘要（装备、附魔各新增、删除、修改了几个）。

## 自动抓取（GitHub Actions）

工作流 `.github/workflows/pvp-equip.yml`：

- **每天北京时间 6:00** 在 GitHub 上跑一次 `build.ts`。数据有变化时先跑 `pnpm test`，通过后以 `github-actions[bot]` 的身份提交到 GitHub 仓库的 `main`，提交说明形如「数据：更新魔盒 PVP 装备（2026-11-21）」，正文是变更摘要。没变化就什么都不提交。
- **手动触发**：GitHub 仓库 → Actions → 「更新 PVP 装备数据」→ Run workflow。勾上「只抓取和校验，不提交」可以只看结果。每次运行的摘要写在运行页面的 Summary 里。
- 校验不过（魔盒接口挂了、数量不对、有附魔请求失败）时，这次运行失败，不提交，等第二天再跑。
- **注意**：
  - 机器人会往 GitHub 的 `main` 提交。本地往 GitHub 推送前，先 `git fetch github && git merge github/main`（或 rebase），再推送 origin 和 github，不要 force push。
  - 公开仓库 60 天没有任何活动时，GitHub 会自动停用定时任务。被停用后到 Actions 页面点「Enable workflow」即可恢复。
  - 新数据要等下次打包发版才会进安装包；已经安装的客户端要更新到新版本才能用上。

也可以在本地手动跑 `build.ts`，跑完先过一遍 `pnpm test` 和截图导入测试，再提交。

## 接口

| 接口 | 用途 |
| --- | --- |
| `equip/{armor,trinket,weapon}?client=std&pv_type=2&order_key=Level&order_by=DESC&per=200&page=N` | PVP 防具、饰品、武器，按品级从高到低翻页 |
| `item/search?client=std&keyword=化劲 / 御劲` | 搜索附魔物品，从说明里的 `ENCHANT <id>` 拿到附魔 id，取最大值当扫描锚点 |
| `resource/std/enchant.<id>` | 附魔详情（属性、装分、品质、部位）。无效 id 返回 HTTP 200 和 `[]` |

每个请求最多重试 4 次，超时 30 秒。魔盒没有附魔列表接口，物品搜索也搜不全（搜「铸世」「附魔」都搜不到），所以附魔按 id 扫：从锚点往前 500 个，往后扫到连续 40 个空号为止，并发 12 个。每个请求约 3 秒，整次运行约 5 分钟。

## 筛选规则

- **当季装备**：品级不低于最高 PVP 品级的 90%。当季品级是 1260–1355，上一季最高是 1095，所以收录的是 ≥ 1220 的装备，共约 2800 件。
- **门派**：按装备的 `BelongSchool` 分文件；没有门派的算通用。新门派要加进 `PVP_SCHOOL_FILE`，否则会打印「没收录的门派」并跳过。
- **小附魔**（`pickEnchants`）：魔盒标了 `_latest_enhance` 的还包括前几季的，所以按装分分当季、往季：同品质（蓝、紫）里，装分不低于最高值 60% 的算当季（当季紫色 105–158、蓝色 42–52；上一季紫色最高 85、蓝色 28）。
  - 当季收：化劲、御劲附魔；系列（名字去掉最后一段，例如「铸世·归正」）里有化劲或御劲、又没有治疗和仇恨附魔的，整个系列都收。所以 PVP 的铸世·归正（戒指、暗器 158 分）收了，PVE 的铸世·息烽没收。
  - 往季收：当季没有的「部位 + 属性」，取往季里装分最高的一个，标 `legacy`，附魔下拉里单独放在「往季」一组。例如帽子、鞋子、武器的内攻（风语，57 分）：当季的攻击附魔都是全攻击，推栏截图里写「内功·攻击」的就是这种往季附魔。
  - 只有治疗属性的不收。原版已有的附魔 id 引擎会跳过，多收不影响。
- **合并到心法**（`pickPvp`）：门派装只合入本门派、本功法的；通用装只合入主属性和心法相同的（例如紫霞功只合入根骨装）。附魔按原版的规则过滤：主属性只要本心法的，武伤只给力道、身法，外功属性只给外功，内功属性只给非外功。
- **属性名**：魔盒的全攻击 `atAllTypeAttackPowerBase`、全破防 `atAllTypeOvercomeBase` 换成原版的 `allAttackPowerBase`、`atAllOvercome`（同原版 `根据外部附魔属性获取ID`），内功分系属性统一成内功属性。
- 同名装备通常有两个品级：门派装 1320/1260，通用装 1355/1280。截图导入时，同名装备取最高品级。
- **截图里的附魔**（`gearScan.ts` 的 `bestEnchant`）：附魔词带「内功 / 内攻 / 内破」只找内功属性的，带「外功」只找外功的，带「全」只找全属性的，范围里没有就不限。PVP 装备取装分最高的；PVE 装备先找 PVE 附魔，没有再找 PVP 和往季的。

## 校验（不通过就退出，不改动旧文件）

- 最高品级 ≥ 1000。
- 当季装备 ≥ 500 件。
- 有通用装备，且帽子、衣服、腰带、护腕、下装、鞋子、项链、腰坠、戒指、暗器都有（通用装没有 PVP 主武器）。
- 至少 15 个门派。
- 化劲、御劲小附魔 ≥ 4 个，PVP 小附魔一共 ≥ 20 个。
- 附魔详情没有请求失败的（漏一个会让结果忽多忽少）。

## 属性怎么算

原版计算器不算化劲、御劲和 PVP 套装属性，这些由引擎补上（`engine.ts` 加上 `pvpEquip.ts` 里的 `pvpDefense`）：

- **化劲%** = min(85%, 化劲等级 / (化劲等级 + 系数) + 102/1024)。基础值 102/1024 约等于 9.96%。每点全能额外给 1 点化劲。
  - 来源：魔盒《130 级属性概述》https://www.jx3box.com/bps/85797 ；85% 上限见 2024-04-25 版本公告。
- **御劲%** = 御劲等级 / 系数。
- 系数取原版计算器常量里的 `化劲`、`御劲`。精炼加成用原版的 `精炼加成系数`。
- **PVP 孔**：普通孔（基数 304）且原版孔表里有这种属性的，直接用原版的孔；体质孔（456）、气血孔、化劲孔等，按「属性@基数」补进孔表，数值用 `holeValue` 计算。
- **PVP 套装**：两件套、四件套里的破防、会心等属性加进装备属性；化劲、御劲算进防御属性。

之前装分差 88（25,499 对 25,411），原因是附魔库少了两类附魔，截图匹配只能拿最接近的顶替：

| 部位 | 截图里的附魔 | 之前匹配成 | 装分 |
| --- | --- | --- | --- |
| 两个戒指 | 铸世·归正·戒指（攻击）：攻击 +126 | 镇渊石：攻击 +90 | 158 → 122，各少 36 |
| 暗器 | 铸世·归正·暗器（元气）：元气 +126 | 镇渊石：元气 +90 | 158 → 122，少 36 |
| 帽子、鞋子、武器 | 往季风语「内功·攻击」：内攻 +39 | 当季全攻击 +90 | 57 → 122，各多 65 |

合计多算了 65×3 − 36×3 = 87 分（25,499 → 25,412）。剩下的 1 分差在别处（破防也差 0.01%），影响很小。补上这两类附魔后，其他属性全部和截图一致。
